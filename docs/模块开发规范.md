# 模块开发规范

> 把「加新模块」变成可复制的标准动作：不改主框架代码，30 分钟跑通一个新场景。

---

## 1. 模块目录结构

每个模块是 `backend/app/modules/<code>/` 下的一个自包含目录：

```
backend/app/modules/m06_energy_analysis/      # 目录名 = manifest.code
├── manifest.yaml          # 模块清单（必填，驱动注册 + 前端渲染）
├── logic.py               # 业务逻辑 + handle 入口（必填）
├── api.py                 # FastAPI 路由（必填，标准 5 行骨架）
├── system.md              # LLM system prompt（按需）
├── user.md                # LLM user prompt 模板（按需）
├── prompts/               # 多 prompt 文件（按需，复杂模块用）
├── schemas.py             # Pydantic 模型（按需，简单模块可省略）
└── seed/                  # 种子知识库（按需，RAG 模块用）
    └── knowledge/
        └── m06_energy_analysis/
            ├── NOTE-01.md
            └── ...
```

**最小集合**：`manifest.yaml` + `logic.py` + `api.py`，三件套即可跑通。

## 2. manifest.yaml 字段规范

```yaml

# 痛点与价值（驱动首页 DeployCard）
pain_points:
  - 能耗异常靠人工巡检发现晚
value_props:
  - 自动识别能耗异常时段并归因

# 输入 schema（驱动前端 SchemaInput 自动渲染表单）
input_schema:
  type: object
  required: [line]
  properties:
    line:
      type: string
      title: 产线
      widget: select            # text | textarea | select | number | file
      options: [A线, B线, C线]
      default: ""
    date_from:
      type: string
      title: 开始日期
      widget: text
      default: ""
    date_to:
      type: string
      title: 结束日期
      widget: text
      default: ""

# 输出 schema（驱动前端 SchemaOutput 自动渲染结果）
output_schema:
  type: object
  properties:
    summary:
      type: string
      title: 分析结论
    anomalies:
      type: array
      title: 异常时段
      items:
        type: object
        properties:
          time: { type: string, title: 时段 }
          value: { type: number, title: 能耗值 }
          reason: { type: string, title: 可能原因 }
    export_url:
      type: string
      title: 报告下载

# 能力声明（可选，告诉前端该模块支持什么）
capabilities:
  - rag                         # 需要 RAG 检索
  - citation                   # 输出带引用来源
  - structured_output           # 输出结构化 JSON
  - export                      # 支持文件导出

# 检索配置（RAG 模块填，非 RAG 模块省略）
retrieval:
  collections: ["energy_manual"]  # 知识库目录名
  top_k: 8
  rerank_top_n: 5

# 演示剧本（DEMO 模式展示推荐问题）
demo:
  suggested_questions:
    - A线最近一周能耗有没有异常
    - B线为什么周二用电量偏高

# 落地条件（首页 DeployCard 展示）
deployment_requirements:
  data_needed:
    - 近 30 天能耗明细（电/水/气，按小时）
    - 产线班次表
  integration: 对接 EMS 或导出 Excel
  timeline: 数据齐备后 2 周上线
  acceptance_criteria:
    - 异常时段识别准确率 > 90%
```

## 3. logic.py 标准骨架

```python
"""M06 能耗分析模块业务逻辑。"""
from __future__ import annotations

import json, logging
from pathlib import Path
from typing import AsyncIterator, Dict, Any

from fastapi import Request
from fastapi.responses import StreamingResponse

from app.config import settings
from app.core import audit
from app.core.llm_gateway import get_gateway

logger = logging.getLogger(__name__)
MODULE_CODE = "m06_energy_analysis"
MODULE_DIR = Path(__file__).resolve().parent


async def handle(payload: dict, request: Request) -> StreamingResponse:
    """模块统一 invoke 入口。"""
    inputs = payload.get("inputs", {}) or {}
    stream = payload.get("stream", True)

    # 1. 输入解析
    line = str(inputs.get("line", "")).strip()
    date_from = str(inputs.get("date_from", "")).strip()
    date_to = str(inputs.get("date_to", "")).strip()

    # 2. 业务逻辑（查库 / RAG 检索 / LLM 生成）
    # ... 你的逻辑 ...

    # 3. 构造结构化结果
    structured: Dict[str, Any] = {
        "summary": "...",
        "anomalies": [...],
    }

    # 4. SSE 返回（标准事件序列）
    async def event_stream() -> AsyncIterator[str]:
        # meta 事件
        yield f"event: meta\ndata: {json.dumps({'module': MODULE_CODE})}\n\n"
        # result 事件（结构化结果，必须用 {"structured": {...}} 包装）
        yield f"event: result\ndata: {json.dumps({'structured': structured}, ensure_ascii=False)}\n\n"
        # done 事件
        yield "event: done\ndata: {}\n\n"

    return StreamingResponse(event_stream(), media_type="text/event-stream")
```

### SSE 事件序列

| 事件 | 时机 | data 内容 |
|------|------|-----------|
| `meta` | 开头 | `{"module": "xxx", "trace_id": "..."}` |
| `chunk` | LLM 流式输出时（多次） | LLM 输出的文本片段 |
| `citation` | LLM 完成后（多次） | 引用来源对象 |
| `result` | 结构化结果就绪 | 完整 output_schema JSON |
| `done` | 结束 | `{}` |

## 4. api.py 标准骨架（5 行）

```python
"""M06 能耗分析模块 API 路由。"""
from __future__ import annotations

from fastapi import APIRouter, Request
from .logic import handle

router = APIRouter()

@router.post("/invoke")
async def invoke(request: Request):
    payload = await request.json()
    return await handle(payload, request)
```

> 需要扩展接口（如 /sample 自动加载样例）时，在同一个 `router` 上加路由即可，
> registry 会自动把 `router` 挂载到 `/api/modules/{code}` 下。

## 6. 新增模块标准 6 步

### Step 1：创建目录

```bash
mkdir -p backend/app/modules/m06_energy_analysis
```

### Step 2：写 manifest.yaml

从上方模板复制，改 `code`/`name`/`input_schema`/`output_schema`。

### Step 3：写 logic.py

从上方骨架复制，实现 `handle()` 函数的业务逻辑。

### Step 4：写 api.py

直接复制 5 行骨架，无需修改（除非要加额外接口）。

### Step 5：加种子知识库（RAG 模块）

```bash
mkdir -p backend/seed/knowledge/m06_energy_analysis
# 放入 .md 知识文件（带 front matter）
```

知识文件格式：
```markdown
---
title: 空压机节能规范
version: V2.0
effective_date: 2025-06-01
tags: [energy, air-compressor]
---

# 空压机节能规范 V2.0

## 1. 排气压力
排气压力每提高 0.1MPa，能耗增加约 6%...
```

### Step 6：重启后端

## 7. 前端渲染机制

模块注册后，前端**零改动**：

- **首页卡片**：`GET /api/registry/modules` 返回模块列表，`DeployCard.vue` 按 `category` 分组渲染
- **输入表单**：`SchemaInput.vue` 读 `manifest.input_schema`，按 `widget` 类型自动渲染（text/textarea/select/number/file）
- **输出展示**：`SchemaOutput.vue` 读 `manifest.output_schema`，自动渲染结构化结果
- **导出链接**：`output_schema` 中 `export_url`/`export_url_pdf` 字段自动渲染为下载按钮

**唯一需要改前端的情况**：模块有特殊交互（如文件上传进度条、图表绑定），需要写专属 Vue 组件并在 router 注册路由。

## 8. 文件上传模块

需要文件上传的模块（如 M02 标书审核）：

1. `input_schema` 中声明 `widget: file`
2. 前端自动渲染上传组件，文件经 `POST /api/files/upload` 上传后返回 `file_id`
3. `logic.py` 从 `inputs.file_id` 拿到 ID，调 `app.api.files.get_path(file_id)` 获取本地路径
4. 用 `core/document_parser.py` 的 `parse_document(path)` 解析 PDF/Word

---

## 9. 导出功能

模块输出中需要导出 Word/PDF 时：

1. `output_schema` 声明 `export_url` 和 `export_url_pdf` 字段
2. `logic.py` 在生成结构化结果后，调用模板渲染：

```python
from app.core.template import render_to_docx, render_to_pdf

docx_path = render_to_docx(MODULE_DIR / "template.yaml", structured, output_path)
pdf_path = render_to_pdf(MODULE_DIR / "template.yaml", structured, output_path)
```

3. 注册文件到 `data/files/exports/`，拿到 file_id
4. `structured["export_url"] = f"/api/files/{file_id}"`
5. 前端 `SchemaOutput.vue` 自动渲染为下载按钮

模板 YAML 格式见 `backend/app/modules/m03_quality_8d/template_8d.yaml`。

## 10. 常见问题

| 问题 | 解决 |
|------|------|
| 模块没出现在首页 | 检查 `manifest.code` 与目录名是否一致（registry 会校验） |
| 前端表单不显示 | 检查 `input_schema.properties` 的 `widget` 字段是否正确 |
| LLM 不调用 | 检查 `.env` 的 `LLM_API_KEY`，DEMO 模式下无 key 会降级 |
| RAG 检索为空 | 检查 `seed/knowledge/<collection>/` 目录是否有 .md 文件 |
| 导出按钮不出现 | `output_schema` 中 `export_url` 字段名必须精确匹配 |
| 时区显示错误 | 时间戳用 ISO 格式存储，前端用 `new Date(t)` 转本地时区 |
