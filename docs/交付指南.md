# 交付指南（现场改造手册）

> 本手册面向实施工程师，覆盖从现场部署、账号开通、模块权限配置到日常运维的完整流程。
> 对应施工蓝图 §6.1（平台表）、§7.1（平台接口）、§11（配置）、§12（生产化）。

## 1. 快速开始（演示模式）

```bash
# 后端（Python 3.9+）
cd backend
pip install -r requirements.txt
cp .env.example .env      # 按需修改 LLM_API_KEY（可留空，走剧本模式）
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 前端（Node 18+）
cd frontend
npm install
npm run dev               # http://localhost:5173
```

DEMO 模式（`DEMO_MODE=true`）下：

- 统一门禁：首页与业务模块均需**登录**（默认账号见 §2）或持**访客时效链接**（§4.4）访问，匿名请求返回 401
- 未配置 `LLM_API_KEY` 时 6 个模块的推荐问题自动走内置剧本，演示不中断（§7）
- 审计日志持久化到本地 SQLite（`backend/data/mfgai.db`）

## 2. 内置账号（首启自动创建）

首次启动时若 `app_user` 表为空，自动创建以下三个角色账号：

| 账号 | 角色 | 权限 |
|------|------|------|
| admin | 管理员 | 全部模块 + 管理与审计页 |
| analyst | 分析员 | 全部业务模块（不可进 /admin） |
| viewer | 一线查看 | 按 `app_module_permission` 白名单 |

初始密码策略（系统不再内置公开口令）：

- **生产模式**（`APP_ENV=prod` 或 `DEMO_MODE=false`）：首启时为每个账号生成 12 位随机初始密码，**仅在后端启动日志中打印一次**，格式为 `初始账号（仅显示一次，请立即登录并改密）`。请从日志抄录后立即登录修改；日志未保留时，只能由管理员通过下方 SQL 重置。
- **本地 DEMO 模式**：同样需要登录（或使用访客链接，见 §4.4）；固定开发口令仅存在于后端代码的 `DEMO_USERS` 常量中，**严禁照搬到生产环境**。

生产环境密码以 pbkdf2-sha256 哈希存储，重置方式：

```sql
-- 用 python 生成新哈希：
-- python -c "from app.core.auth import hash_password; print(hash_password('新密码'))"
UPDATE app_user SET password_hash='pbkdf2$120000$...' WHERE username='admin';
```

## 3. 生产部署（DEMO_MODE=false）

### 3.1 环境变量

拷贝 `deploy/.env.example`（本机直接跑后端则用 `backend/.env.example`）并修改：

```ini
DEMO_MODE=false            # 关闭演示种子数据（鉴权两种模式均生效）
APP_ENV=prod
SECRET_KEY=<必填>          # JWT 签名密钥；为空/弱值/短于16字符时后端拒绝启动
                           # 生成：python -c "import secrets;print(secrets.token_hex(32))"
RATE_LIMIT_PER_MINUTE=20   # 公网防刷限流（每 IP 每分钟请求数）

# CORS 白名单：逗号分隔的前端来源；生产环境禁止 *，否则后端拒绝启动
CORS_ORIGINS=https://your-app.pages.dev

# 数据库：生产建议 postgres
DB_DRIVER=postgres
DB_HOST=db
DB_PORT=5432
DB_NAME=mfgai
DB_USER=mfgai
DB_PASSWORD=<强密码>

# LLM：指向客户模型或本地 vLLM（只存后端，永不下发前端）
LLM_BASE_URL=https://api.deepseek.com/v1   # 或 http://<内网vLLM>:8000/v1
LLM_API_KEY=<客户密钥>
```

前端静态部署（Cloudflare/EdgeOne Pages）时，构建期设置 `VITE_API_BASE` 指向后端公网地址，
模板见 `frontend/.env.example`。访客链接相关阈值见 `GUEST_*` 变量（默认 1h/30 次/5 次每分钟）。

### 3.2 Docker Compose 部署

```bash
cd deploy
cp .env.example .env      # 按上节修改
docker compose up -d --build
```

服务拓扑：`db`（pgvector:pg16）→ `backend`（:8000）→ `frontend`（:80/nginx）。

### 3.3 生产模式行为变化

| 行为 | DEMO 模式 | 生产模式 |
|------|-----------|----------|
| 业务模块 invoke | 需登录或访客令牌 | 需登录或访客令牌 |
| /api/admin/* | 仅 admin 角色（401/403） | 仅 admin 角色（401/403） |
| 文件上传 | 需登录 | 需登录 |
| 文件下载 / 模块 GET / registry | 登录或访客令牌（访客白名单内） | 同左 |
| /api/health、/api/auth/login、/api/guest/verify | 公开（免鉴权） | 公开（免鉴权） |
| 匿名访问业务接口 | 401 | 401 |
| 限流 | 生效（本地可放宽） | 生效（建议 20/IP/分钟；访客另限 5 次/分钟） |

## 4. 鉴权与模块级权限

### 4.1 技术形态

- JWT：HS256（stdlib 实现，无第三方依赖），默认 12 小时有效
- 口令：pbkdf2-sha256，120,000 轮迭代
- 注入点：`app/main.py` 平台中间件统一拦截，业务模块零改动

### 4.2 viewer 白名单配置

viewer 角色按 `app_module_permission` 表控制可见模块（**白名单为空 = 全放行**）：

```sql
-- 只允许 viewer 访问 SOP 问答
INSERT INTO app_module_permission (user_id, module_code)
SELECT id, 'm04_sop_qa' FROM app_user WHERE username='viewer';
```

admin/analyst 角色不受白名单限制。未授权 viewer 调用受限模块返回 `403`。

### 4.3 平台五表（§6.1）

| 表 | 用途 | 初始化 |
|----|------|--------|
| app_user | 账号与角色 | 首启自动种子三账号 |
| app_module_permission | viewer 模块白名单 | 手工配置 |
| app_audit_log | 审计日志 | 自动写入 |
| app_module | 模块清单 | 每次启动自动同步自 manifest |
| app_guest_token | 访客时效链接（有效期/次数/吊销/真实 LLM 配额） | 管理页生成 |

幂等建表在每次启动时自动执行（sqlite 与 postgres 双方言），无需手工执行 DDL。

### 4.4 访客时效链接（对外演示）

管理员在 `/admin`「访客链接」面板签发，无需给客户开账号：

- **有效期**：1 / 6 / 24 小时可选（`GUEST_DEFAULT_HOURS`）；到期后链接立即失效
- **调用次数**：默认 30 次（`GUEST_MAX_CALLS`），每次 invoke 扣减；用尽返回结束页
- **频率限制**：每令牌每分钟最多 5 次 invoke（`GUEST_RATE_PER_MINUTE`）
- **路径隔离**：访客只能访问模块列表/只读详情/invoke/文件下载；管理接口 403
- **LLM 配额**：默认访客全程走剧本模式（不消耗客户 Key）；勾选「允许真实 LLM」后可设配额
  （`GUEST_REAL_LLM_MAX`），超出自动切回剧本
- **吊销**：管理页一键吊销，立即生效
- 访问形态：链接带 `?t=<jwt>`，前端核验后转存 sessionStorage；导出下载支持 `?t=` 直达；
  到期/吊销/超次统一跳转 `/expired` 结束页，不暴露任何业务内容

## 5. 审计与统计

- 全部 AI 输出经 `core/audit.audit_log` 记录：**谁（user_id）何时（created_at）问什么（question）答什么（answer）引用了什么（citations）**，含模型、延迟、token、状态（success/degraded/failed）、trace_id
- 管理页（`/admin`）提供：调用统计卡、近 7 日趋势、模块分布、多条件筛选（模块/状态/动作/关键词）、行展开查看问题/回答/引用、分页
- 接口：`GET /api/admin/audit?module=&status=&action=&q=&limit=&offset=`、`GET /api/admin/stats`
- 持久化失败自动回退内存缓冲，不影响业务

## 6. 报告导出（Word / PDF）

M03 质量 8D 与 M02 标书审核结果页均提供**双格式下载**：

- Word（.docx）：`core/template.render_to_docx`，宋体正文/黑体标题，D1-D8 完整章节
- PDF（.pdf）：`core/template.render_to_pdf`，PyMuPDF 内置中文字体（china-s），A4 版式、页码、网格表格

报告先落到 FileStore（`data/files/exports/`），注册后经 `GET /api/files/{file_id}` 下载
（中文文件名走 RFC 5987 编码）。

两种报告的封面副标题与页脚均带 AI 免责声明（"AI 生成内容须由工程师审核确认"），
Word/PDF 均渲染；模板措辞可在 `seed/template_*.yaml` 的 `subtitle`/`footer_note` 修改。

## 7. 容错降级

- 剧本模式（无 Key 也能演示）：未配置 `LLM_API_KEY`、Key 失效或访客超出真实 LLM 配额时，
  6 个模块的推荐问题命中 `seed/demo_scripts.json` 内置剧本，返回确定性样例答案，
  流式输出/引用/导出链路完整，UI 明确标注"模拟数据"
- LLM 运行时故障（网络失败/超时）：`llm_gateway` 指数退避重试后降级
  - M04：降级到检索命中的原始条款拼接（明确标注“LLM 不可用”），绝不编造
  - M03/M02：结构化兜底输出，结果状态标记 `degraded`
- 数据库写失败：审计回退内存缓冲
- 降级调用照常记入审计（status=degraded），管理页可见

## 9. 现场适配点清单

| 适配点 | 位置 | 说明 |
|--------|------|------|
| 数据接入 | `adapters/`（C3） | 客户专有数据库/文件系统驱动，唯一代码级落点 |
| 术语口径 | `adapters/terminology.yaml` | 客户行话 → 标准术语映射 |
| 提示词覆盖 | 各模块 `prompts_override/` | 不改原 prompts，放同名文件即覆盖 |
| 报告模板 | `app/modules/m03*/seed/template_8d.yaml` 等 | 客户现行报告版式 |
| LLM 接入 | `LLM_*` 环境变量 | OpenAI 兼容协议即可（vLLM/Ollama/云 API） |
| 模块权限 | `app_module_permission` 表 | 见 §4.2 |

## 10. 故障排查

| 现象 | 排查 |
|------|------|
| LLM 不通 | `GET /api/health` 看 `llm.ok/llm.error`；确认 `LLM_BASE_URL` 可达、Key 有效 |
| 登录报"用户名或密码错误" | 确认 `app_user` 有该账号且 enabled=1；重置见 §2 |
| 调用返回 401 | 前端未带 token 或已过期（12h）→ 重新登录；访客令牌失效会自动跳转 /expired |
| 调用返回 403 | viewer 未配置模块白名单 → 见 §4.2；访客访问白名单外接口（如 /api/admin）同样 403 |
| 调用返回 429 | 触发限流，调整 `RATE_LIMIT_PER_MINUTE` 或稍后再试；访客为 5 次/分钟或总次数用尽 |
| 导出下载 404 | 后端重启后进程内文件注册表清空 → 重新生成报告 |
| PDF 中文乱码 | 确认 PyMuPDF 版本 ≥ 1.24（内置 china-s 字体） |
| 前端代理不通 | 开发态确认 vite proxy 指向 :8000；生产态配 `VITE_API_BASE` |
